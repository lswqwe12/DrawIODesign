# 部署说明：GitHub Pages + GitHub Actions

本项目已改造为可静态导出，并通过 GitHub Actions 自动部署到 GitHub Pages。
以下说明部署步骤，以及 **模型 API Key 的处理方式**（关键）。

## 一、本地开发（不变）

本地开发仍走服务端代理：`src/app/api/ai/*` 的 Route Handler 负责调用 DeepSeek，
密钥从 `.env.local` 读取（`DEEPSEEK_API_KEY`），**保留在服务端、不暴露给浏览器**。

```
# .env.local
DEEPSEEK_API_KEY=sk-xxx
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
```

此时 `streamAI` 检测到没有 `NEXT_PUBLIC_DEEPSEEK_API_KEY`，自动走 `/api/ai/*` 代理。

## 二、部署到 GitHub Pages

### 1. 推送代码到 GitHub

项目已包含：
- `next.config.ts`：`output: "export"`（静态导出到 `out/`）+ `basePath`/`assetPrefix`。
- `.github/workflows/deploy.yml`：自动构建并发布到 Pages。

### 2. 开启 Pages 并选择 Actions 作为来源

GitHub 仓库 → **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。

### 3. 配置仓库 Secrets（关键）

仓库 → **Settings → Secrets and variables → Actions → New repository secret**：

| Secret 名称 | 必填 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 是 | DeepSeek 密钥，构建时注入 `NEXT_PUBLIC_DEEPSEEK_API_KEY` |
| `DEEPSEEK_BASE_URL` | 否 | 默认 `https://api.deepseek.com`；可指向自建代理 |
| `DEEPSEEK_MODEL` | 否 | 默认 `deepseek-chat` |

### 4. 触发部署

推送 `main` 分支（或手动 **Actions → Run workflow**）即自动构建发布。
站点地址为 `https://<用户名>.github.io/<仓库名>/`。

## 三、API Key 如何处理（重点）

GitHub Pages 是纯静态托管，**没有服务端**，原 `/api/ai/*` 代理无法运行。
因此当前方案在静态部署时由浏览器**直连 DeepSeek**（DeepSeek 已开启 CORS），
密钥通过 `NEXT_PUBLIC_DEEPSEEK_API_KEY` 在**构建时内联进客户端 JS bundle**。

### ⚠️ 安全风险

`NEXT_PUBLIC_*` 变量会明文出现在前端产物中，任何人打开页面源码/抓包即可拿到密钥。
因此该方案**仅适合比赛演示等低风险场景**。

演示环境请务必：
1. 使用**受限额度**的独立 Key（如新建一个只读/低限额 Key，用完即废）；
2. 比赛结束后**立即在 DeepSeek 后台吊销该 Key**，避免被盗用产生费用；
3. 不要复用生产环境 Key。

### 生产环境推荐：改用服务端代理

如需在生产使用，请把密钥留在服务端，方案如下（无需改动业务代码）：

1. 用 Cloudflare Workers / Vercel Function 等部署一个 OpenAI 兼容的 `/chat/completions` 代理，
   内部转发到 DeepSeek 并把密钥放在该代理的环境变量里；
2. 部署时把 `NEXT_PUBLIC_DEEPSEEK_BASE_URL` 指向该代理地址（`NEXT_PUBLIC_DEEPSEEK_API_KEY` 留空，
   或填代理自己的鉴权 token）；
3. 前端仍走 `streamAI`，只是把请求发到代理，密钥不再进入客户端 bundle。

## 四、双通道自动切换逻辑

`src/services/aiService.ts` 的 `streamAI` 会按如下规则自动选择通道：

```
配置了 NEXT_PUBLIC_DEEPSEEK_API_KEY ？
  ├─ 是 → src/services/aiClient.ts 浏览器直连 DeepSeek（GitHub Pages 静态部署）
  └─ 否 → /api/ai/* 服务端代理（本地开发 / 自托管，密钥在服务端）
```

两套通道共用同一套提示词与消息构建逻辑（`src/lib/aiPrompts.ts`），行为一致。

## 五、子路径（basePath）说明

工作流会自动计算 `NEXT_PUBLIC_BASE_PATH`：
- 项目站点（`用户名.github.io/仓库名`）→ `/仓库名`；
- 用户站点（`用户名.github.io`）或自定义域名 → 空。

本地手动构建项目站点时，可显式传入：

```bash
NEXT_PUBLIC_BASE_PATH=/仓库名 NEXT_PUBLIC_DEEPSEEK_API_KEY=sk-xxx npm run build
```
