# 后续优化与开发路线图

> 基于当前代码现状（2026-08）整理，用于指导后续迭代。
> 优先级：**P0** 近期必做 / **P1** 重要 / **P2** 远期增强。

---

## 〇、当前现状盘点（基线）

已落地能力：

- 文件管理：IndexedDB 存储、无限层级文件夹、文件 CRUD、重命名/移动/复制/删除、导入 `.drawio`/`.xml`、按名搜索、树形目录 + 右键菜单。
- 编辑器：`react-drawio` 集成（`ui=min`），自动保存（500ms 防抖）、显式保存（xmlsvg 导出回读）、导出 PNG/SVG。
- 保存保护：切换文件弹「保存/不保存/取消」、`beforeunload` 关闭提醒、打开文件与树节点关联、AI 生成自动保存并激活。
- AI：一句话生成 UML（流式 SSE，`sanitizeGeneratedCells` 净化）、图表解读（XML 优先 / PNG 备选）。
- 测试：`xml-helper` 14 个单元测试。

已知短板（对应后文各节）：

1. 大量交互仍用原生 `window.prompt/confirm/alert`，体验粗糙。
2. 数据仅存 IndexedDB，换浏览器/清缓存即丢失，无备份与迁移。
3. AI 只支持「一次性生成」，不支持多轮增量修改（spec 2.3.2 已要求但未实现）。
4. 状态模型已支持多文件（`Map<fileId, DiagramState>`），但 UI 没有标签页（Tab Bar），无法直观切换已打开文件。
5. 未实现拖拽移动、面包屑、视图切换、键盘快捷键等 spec 中提及的交互。

## 一、UI 优化

### 1.1 用 shadcn 组件替换原生弹窗【P0】
- **现状**：新建/重命名/移动用 `window.prompt`，删除用 `window.confirm`，错误用 `window.alert`。
- **目标**：统一为 `Dialog` / `AlertDialog` / `DropdownMenu` / `Toast`。
- **需求**：
  - 引入 shadcn `dialog`、`alert-dialog`、`dropdown-menu`、`toast`（sonner 或自定义）组件。
  - 新建/重命名改为受控表单弹窗，支持回车确认、输入校验（重名、空值、非法字符）。
  - 删除、移动、未保存切换统一走 `AlertDialog` / 现有 `UnsavedChangesDialog`。
  - 保存成功/失败、导入结果用 Toast 反馈（当前保存失败仅有状态灯，无提示）。

### 1.2 多标签页 Tab Bar【P0】
- **现状**：`DiagramContext` 已维护 `Map<fileId, DiagramState>`，但 UI 只显示单个活跃文件，切换靠目录树双击。
- **目标**：编辑器顶部增加标签栏，展示已打开文件，点击切换、右键关闭、关闭时走未保存拦截。
- **需求**：
  - 新增 `EditorTabs` 组件，订阅 `states` + `activeFileId`。
  - 标签显示文件名 + 脏标记（●），点击调 `requestOpenFile`。
  - 关闭标签：若 dirty 弹「保存/不保存/取消」，取消则中止关闭。
  - 与目录树选中态保持双向同步。

### 1.3 空状态与新手引导【P1】
- **现状**：无文件时树形目录为空，只有一行「无匹配」提示，新用户不知从何下手。
- **需求**：
  - 根目录为空时展示引导插画 + 「新建文件 / 导入文件」按钮。
  - 首次进入可展示轻量 onboarding（3 步：新建文件 → 拖拽图形 → 让 AI 生成）。
  - 空 AI 面板已有文案，可补充快捷指令模板。

### 1.4 暗色模式【P1】
- **现状**：`globals.css` 已定义 `.dark` 主题变量，但无切换入口。
- **需求**：
  - 引入 `next-themes` 或自实现，TopBar 增加主题切换。
  - 注意 draw.io 编辑器 iframe 需同步 `ui=dark` 主题（`config/drawio.ts` 已支持 `ui` 值，需动态切换）。

### 1.5 顶栏与状态栏信息补全【P1】
- **现状**：TopBar 仅保存/导出按钮；StatusBar 仅保存状态灯 + 「自动保存 · 500ms」。
- **需求**：
  - TopBar 左侧展示应用名/Logo、当前文件名（可编辑重命名）。
  - StatusBar 增加当前文件路径、图表元素数量、最后保存时间、AI 面板快捷开关。

### 1.6 文件缩略图预览【P2】
- **现状**：`latestSvg` 已有导出 SVG，但未用于展示。
- **需求**：文件列表（网格视图）用 `latestSvg` 或导出 SVG 作为缩略图；可缓存到 IndexedDB。

### 1.7 响应式与平板适配【P2】
- **现状**：布局为三栏 `ResizablePanelGroup`，未针对窄屏优化。
- **需求**：窄屏下折叠文件树 / AI 面板为抽屉，保证编辑器可用。

## 二、交互优化

### 2.1 拖拽移动文件/文件夹【P0】
- **现状**：spec 2.1.1 要求拖拽，但当前仅右键「移动」。
- **需求**：
  - 使用 `dnd-kit` 或原生 HTML5 DnD，实现文件/文件夹拖入目标文件夹、拖到面包屑/根目录。
  - 拖拽时高亮合法目标、禁止拖入自身子树（复用 `fileService.isInSubtree` 逻辑）。

### 2.2 键盘快捷键【P1】
- **需求**：
  - `Ctrl/Cmd + S` 显式保存；`Ctrl/Cmd + E` 导出 PNG；`Ctrl/Cmd + K` 命令面板/搜索聚焦。
  - 新建文件/文件夹、切换面板快捷键。
  - 注意与 draw.io iframe 内部快捷键冲突，需在宿主层拦截或仅在编辑器失焦时生效。

### 2.3 面包屑导航【P1】
- **现状**：spec 要求但未实现，树形目录已合并文件夹+文件。
- **需求**：树形目录顶部展示当前路径面包屑，点击跳转；新建/导入目标随面包屑更新。

### 2.4 最近打开文件【P1】
- **需求**：IndexedDB 记录最近打开时间，目录树或顶栏提供「最近」快捷入口。

### 2.5 命令面板（Cmd+K）【P2】
- **需求**：全局命令面板，支持搜索文件、执行操作（新建/导入/导出/AI 生成/切换主题）。

### 2.6 视图切换（列表/网格）【P2】
- **现状**：spec 提到列表/网格切换，当前仅树形列表。
- **需求**：文件列表支持网格视图（配合缩略图 1.6）。

### 2.7 文件操作撤销/重做【P2】
- **需求**：对重命名/移动/删除提供撤销（Toast 内「撤销」按钮 + 最近操作栈）。

### 2.8 操作反馈与加载态【P0~P1】
- **现状**：保存中仅状态灯；AI 生成中仅「停止」按钮 + 消息流。
- **需求**：导入/保存/导出增加进度与 Toast；AI 生成增加骨架屏/打字机效果（已流式，可优化渲染）。

## 三、AI 能力增强

### 3.1 多轮对话式迭代修改【P0】
- **现状**：spec 2.3.2 要求「基于当前 XML 增量修改」，当前 `generate` 每次新建文件，无上下文。
- **需求**：
  - 生成后保留当前图表 XML 作为对话上下文，支持「把 User 类改成中文名」「新增一个 Order 类」等增量指令。
  - 后端 `generate/route.ts` 增加系统提示词约束「在现有 mxCell 基础上增删改，不重建无关部分」；输入携带当前 `extractMxCells(xml)`。
  - 结果合并后走 `loadDiagram`（复用 `sanitizeGeneratedCells` + `wrapMxCells`）。
  - 支持「生成到当前文件」与「生成到新文件」两种模式。

### 3.2 生成结果确认/重试/回滚【P0】
- **现状**：生成即覆盖当前打开文件，无预览与回滚。
- **需求**：
  - 生成后先展示可对比的预览（旧 XML vs 新 XML 差异），确认后应用；或保留「撤销本次 AI 修改」。
  - 失败时提供「重试」按钮（当前需手动重新输入）。

### 3.3 图表类型识别与模板【P1】
- **需求**：
  - 前端提供图表类型选择器（类图/时序图/用例图/流程图/ER 图），注入到生成提示词。
  - 内置常用模板库（空白类图、登录时序图、ER 图），一键载入。

### 3.4 图表校验与修复建议【P1】
- **需求**：
  - 新增「校验」入口：对当前图表做 UML 规则检查（孤立节点、悬空连线 source/target、重复类名等），输出问题清单。
  - 结合 AI 给出修复建议或一键修复。

### 3.5 批量生成与草稿箱【P2】
- **需求**：一次生成多张图（如按模块拆分）；AI 面板支持草稿暂存与多轮会话历史持久化。

### 3.6 模型与成本治理【P1】
- **现状**：`DEEPSEEK_MODEL` 写死 `deepseek-chat`，无 token 统计、无重试。
- **需求**：
  - 增加上游调用重试、超时、限流（服务端简单令牌桶）。
  - 记录每次调用 token/耗时，用于成本统计；`temperature` 等参数可配置。

## 四、编辑器能力增强

### 4.1 自动布局【P1】
- **现状**：`react-drawio` 已定义 `ActionLayout`（`{ action: 'layout', layouts: [...] }`），未使用。
- **需求**：工具栏增加「自动布局」按钮，调用 `drawioRef` 的布局动作（垂直/水平树、流程图布局），改善 AI 生成图排布。

### 4.2 导出能力扩展【P1】
- **现状**：仅 PNG / SVG 下载，文件名固定 `diagram-<时间戳>`。
- **需求**：
  - 导出 `.drawio` / `.xml` 文件、复制 XML/SVG 到剪贴板、导出 PDF。
  - 导出文件名使用当前文件名，支持格式选择弹窗。

### 4.3 编辑器主题与图形库【P2】
- **需求**：动态切换 `ui` 主题；支持自定义图形库（`libraries` 参数 / 自定义 mxLibrary）。

### 4.4 撤销/重做桥接【P2】
- **需求**：宿主层暴露「撤销/重做」按钮，转发 draw.io 的 undo/redo（需确认 `react-drawio` 是否暴露该动作，否则通过 `postMessage` 扩展）。

## 五、数据与后端（本地优先 → 云化）

### 5.1 数据备份与迁移【P0】
- **现状**：数据仅 IndexedDB，清缓存/换浏览器即丢失。
- **需求**：
  - 一键导出/导入整库（JSON 归档），支持拖拽恢复。
  - 定时提示备份；导出时包含文件夹结构与全部 `.drawio` 内容。

### 5.2 后端 + 云数据库【P1】
- **现状**：纯前端 IndexedDB，无账号。
- **需求**：
  - 引入后端（Next.js Route Handler + PostgreSQL/SQLite + 对象存储），文件元信息入库、XML 存对象存储或库内。
  - 设计好 `fileService` 的抽象层（当前已按 service 分层，便于替换存储实现）。
  - 提供「本地模式 / 云端模式」切换，MVP 兼容离线。

### 5.3 账号与多端同步【P1】
- **需求**：登录（OAuth/邮箱）、跨设备同步、冲突检测（多端编辑同一文件）。

### 5.4 版本历史【P1】
- **需求**：记录文件修改历史（快照），支持查看/回滚/对比任意版本。

### 5.5 协作与分享【P2】
- **需求**：只读分享链接、实时协作（OT/CRDT，工程量大，建议远期）。

## 六、工程化与质量

### 6.1 测试补全【P0】
- **现状**：仅 `xml-helper` 单测。
- **需求**：
  - `fileService` / `FileSystemContext` 单测（mock IndexedDB）。
  - `DiagramContext` 保存/切换/未保存拦截逻辑单测。
  - Playwright E2E：新建→编辑→切换→保存→重开全链路。

### 6.2 错误监控与日志【P1】
- **需求**：接入 Sentry 捕获前端异常与 API 错误；AI 调用失败上报。

### 6.3 CI/CD【P1】
- **需求**：GitHub Actions 跑 `lint` + `test` + `build`，PR 门禁；自动部署。

### 6.4 性能优化【P1】
- **现状**：文件树全量渲染、AI 大 XML 字符串拼接、保存频繁读库。
- **需求**：
  - 文件树大数据量虚拟滚动；`files` 列表节流更新（当前保存后未刷新 store，已在打开时补救，可进一步做增量同步）。
  - 编辑器加载缓存、AI 流式渲染节流（`requestAnimationFrame` 合并 setState）。

### 6.5 无障碍（a11y）【P2】
- **需求**：按钮 aria-label、键盘导航、焦点管理、颜色对比度。

## 七、安全与合规

- **密钥管理【P0】**：API Key 仅存服务端（已满足）；已从 README 移除泄露的硬编码 Key；定期轮换、改用 Secret Manager。
- **XSS 防护【P1】**：draw.io XML 由 LLM 生成，已做属性转义 + 标签栈净化；导入文件走 DOMParser 校验，需继续防御 `javascript:` / 外部实体（XXE）。
- **速率限制【P1】**：`/api/ai/*` 增加请求频率与单次体积限制，防止滥用刷量。
- **数据隐私【P1】**：本地模式数据不出本机；云端模式需加密存储与传输（HTTPS）、明确隐私政策。
